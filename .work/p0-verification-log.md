## OPT-3.1 Markdown 渲染缺口 —— ✅ 已实测通过

**验证脚本**：`.work/verify-31-render.mjs`
**方法**：复刻 `test/smoke-render.test.mjs` 的切片机制，从 `lib/client.js` 切出 `// ── 常量与工具` 到 `// ── 主页面` 的整段，注入 6 个 hook 桩后用 `new Function` 求值，取得真实 `renderMarkdown` 并渲染一段综合样例。

**命令**：`node .work/verify-31-render.mjs`

**实测产出标签计数**：
```
{"h4":1,"span":21,"h5":1,"h6":1,"div":2,"b":2,"em":1,"a":1,"table":1,
 "thead":1,"tr":3,"th":3,"tbody":1,"td":6,"ul":1,"li":3,"input":2,
 "blockquote":1,"pre":1,"code":1}
```

**逐项核对（优化清单 §3.1 要求的能力）**：

| 能力 | 优化前 | 实测结果 |
|---|---|---|
| 表格 table/thead/tbody/tr/th/td | ❌ 完全缺失 | ✅ 3 行 × 3 列，`td x6` 正确 |
| 表格对齐标记 `:--` / `--:` | ❌ | ✅ 分隔行正确识别，未产出内容行 |
| h4 / h5 / h6 | ❌ 只到 h3 | ✅ 各 1 个 |
| `[文字](https://url)` 标准链接 | ❌ | ✅ 生成 `<a>` |
| `*斜体*` | ❌ | ✅ 生成 `<em>` |
| 任务列表 `- [ ]` / `- [x]` | ❌ | ✅ 生成 `<input type=checkbox>`，勾选态正确 |
| 围栏内 `# 注释` 不被当标题 | ❌ 会误判 | ✅ h1 计数 = 0 |

**安全性反向验证**：
- `[点我](javascript:alert(1))` → **未**生成 `<a>`，保持字面文本。C1 的实现注释写明「正则只接受 http(s)」，实测成立。

**结论**：OPT-3.1（P0）功能真实生效，非纸面修复。
